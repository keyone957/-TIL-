### 템플릿

> 자료형을 고정하지 않고 재사용 가능한 함수나 클래스를 만들 수 있는 기능

c++에서 템플릿 특수화가 가능해 특정 타입에 대해서는 다른식으로 동작하게끔 만들 수 있음 vector가 템플릿 특수화의 좋은 예시

* **템플릿 특수화**
  
  > 특정 매개변수에 대해서는 별도 처리를 하고 싶은 경우 특수화 개념을 이용함
  
  ex)
  
      #include<iostream>
      using namespace std;
      template <typename T>
      T max(T a, T b){
         return (a > b ? a : b);
      }
      
      template<>
      double max(double a, double b)
      {
         cout << a << " " << b << "중 큰수는 ? " <<endl;
         return (a > b ? a : b);
      }
      
      int main()
      {
        cout << max(5, 6) << endl;
        cout << max(12.5, 16.7) << endl;
      
        return 0;
      }
      출력
      6
      12.5 16.7 중 큰수는 ?
      16.7
  
    위 결과와 같이 특정 자료형(위에서는 double)에 대해서만 특수화된 템플릿 함수가 호출되게 됨

* 템플릿 특수화의 좋은 예시 vector
  원래 vector<T>는 원소 하나당 최소 1바이트 (8비트)를 씀
  근데 bool은 참 거짓 두가지 뿐이라 1비트만 쓰면됨
  그냥 일반 방식대로 만들면 메모리를 8배 낭비함
  따라서 vector는 bool에 대해서만 특별히 다르게 구현해서 비트 단위로 압축 저장하게 만들었음

#### 장점

* 코드 재사용성 향상

* 컴파일러가 컴파일 타임에 템플릿 인스턴스에 대한 코드를 만들어주기에 런타임에서 속도 이득이 있음

* 컴파일 타임에 다형성 부여가 가능하기에 vtable이 없어 더 빠르게 동작함

* 타입만 다른 중복 코드를 한군데 모을 수 있음
  
  #### 단점

* 컴파일 타임에 인스턴스 생성으로 인해 컴파일 타임이 늘어남
  
  * 템플릿 매개변수로 들어온 종류가 많을수록 늘어남

* 다형성이 추가될 경우 파일이 커지게 되어 실행 시간이 늘어날 수 있다
  
  </aside>

### 가상함수의 단점

1. 호출 비용이 조금 더 든다.
   * 런타임에 vtable을 통해 어떤 함수를 호출할 지 찾아야함
   * vptr → vtable 확인 → 실제 함수 호출
   * 따라서 일반 함수보다는 호출 비용이 조금더 듦
2. 메모리 비용이 증가함
   * 가상함수가 있는 객체는 보통 vptr을 추가로 가진다.
   * 클래스마다 가상함수 주소를 저장하는 vtable이 생성된다.
   * 그래서 일반 클래스보다 객체 크기가 커질 수 있다.
* ### Array vs Vector vs List
  
  <aside>
  
  ### Array
  
  * 고정 크기 배열 → 크기가 컴파일 타임에 결정됨
    
    * 크기 변경 불가
  
  * 스택에 할당
    
    * **메모리에 연속적으로** 저장 ⇒ 캐시 지역성 최고!
  
  * 시간 복잡도
    
    * 인덱스 접근 `$O(1)$`
    
    * 검색 `$O(n)$`
    
    * 중간 삽입, 삭제 X  
      
      </aside>
  
  <aside>
  
  ### Vector
  
  * 동적 배열
  
  * **메모리가 연속적임** ⇒ 캐시 효율 굳 ⇒iterator 연산자를 이용한 접근 가능
    
    * 힙에 연속된 메모리 블록으로 할당
  
  * 시간 복잡도
    
    * 인덱스 접근 `$O(1)$`
    
    * 검색 `$O(n)$`
    
    * 데이터 끝에 추가 삭제 `$O(1)$`
    
    * 중간 삽입 삭제 `$O(n)$`  
      
      </aside>
  
  <aside>
  
  ### List
  
  * 양방향 연결리스트 ⇒ **연속된 메모리 X** ⇒ 각 노드가 포인터로 연결되어있음
  
  * 각 노드가 힙의 서로 다른 위치에 생성됨
    
    * 캐시 미스 많아
  
  * 요소마다 앞 뒤 노드를 가리키는 포인터를 포함하고 있어 추가 메모리 사용.
  
  * 시간 복잡도
    
    * 인덱스 접근 `불가능` ⇒순차 접근만 가능
    
    * 중간 삽입 삭제 `$O(1)$`  
      
      </aside>
  
  
  
  <aside>
  
  ### C# List vs C++ Vector
  
  ### 공통점
  
  > 둘 다 내부적으로 연속된 메모리 블록 동적 배열 사용.  
  > 빠른 인덱스 접근  
  > 높은 캐시 효율
  
  ### 차이점
  
  > 메모리 관리 방식이 가장 큰 차이
  
  C++ vector
  ⇒ 직접 사용자가 메모리 관리를 통해 높은 성능 최적화를 달성할 수 있음
  벡터의 메모리 할당 해제 크기 조정을 제어 할 수 있음
  C# List
  ⇒ GC 를 이용하여 메모리 관리를 자동으로 처리함
  리스트의 크기 조정은 자동으로 이루어지며 사용자는 메모리 관리를 신경 쓸 필요가 없습니다.
  
  </aside>
